# spec — #478 Stale report.golden.json fixtures (unknown vs beneficiary)

## Problem

`test/fixtures/disburse/report.golden.json` (output index 1) records
`"role": "unknown"`. Since 100e8e6e ("classify disburse destination
outputs as beneficiary") `classifyOutputRole`
(`lib/Amaru/Treasury/Report/Classify.hs`) returns `OutputBeneficiary`
for every index in `brBeneficiaryOutputs`, which
`lib/Amaru/Treasury/Build/Disburse.hs` populates. The intended role for
that output is therefore `beneficiary`.

`test/fixtures/withdraw/report.golden.json` (output index 0) records
`"role": "unknown"`. `lib/Amaru/Treasury/Build/Withdraw.hs` sets
`brBeneficiaryOutputs = []` and `brTreasuryLeftoverOutput = Nothing`,
so the current writer also emits `unknown` there. Whatever the real
writer emits for the withdraw fixture is the accepted golden; this
ticket changes no classification.

Both files are only read as inputs (`ReportRenderActionGoldenSpec`
renders them to `report.golden.md`; `ReportSpec` decodes the withdraw
one). The `UPDATE_GOLDENS=1` path regenerates them, but the default
path never compares a regeneration with the committed bytes, so drift
is silent. `swap` and `treasury-inspect` goldens are already compared.

## User story

US-1 — As a maintainer, when the report writer's output for a checked-in
build fixture changes, the golden suite fails until the committed
`report.golden.json` is regenerated, so a fixture never silently
disagrees with the code.

## Requirements

- REQ-1 — `test/fixtures/disburse/report.golden.json` and
  `test/fixtures/withdraw/report.golden.json` are byte-identical to the
  real writer's output for their fixture inputs (produced by the
  writer, not hand-edited).
- REQ-2 — The default golden run regenerates every tracked
  `report.golden.json` from its fixture inputs with the real writer and
  compares it byte-for-byte with the committed file.
- REQ-3 — No production behaviour change: nothing under `lib/`, `app/`,
  `docs/assets/`, CLI surface or schemas changes.

## Invariants

| ID | Holds when | Fails when |
|---|---|---|
| INV-1 | the disburse golden's output 1 has `"role": "beneficiary"`, the role `classifyOutputRole` returns for it | it says anything else |
| INV-2 | each of the disburse and withdraw `report.golden.json` equals, byte-for-byte, the real writer's regeneration from its fixture dir | any byte differs |
| INV-3 | for every tracked `test/fixtures/**/report.golden.json` (extent discovered with `git ls-files`), a default (no `UPDATE_GOLDENS`) golden-suite run regenerates it and fails on any byte difference; on current `main` that run is RED because of the stale disburse role | some tracked `report.golden.json` is read without being compared to a regeneration, or the comparison is skipped/vacuous, or it passes on `main` |
| INV-4 | dependent goldens (`report.golden.md` for disburse/withdraw) are regenerated by the same real path and the suite is green | a dependent golden is hand-edited or left stale |
| INV-5 | `git diff origin/main -- lib app docs/assets` is empty | any production file changes |

## Non-goals

- Changing the withdraw deposit output's role (a classification change
  is a production change; out of scope).
- Changing the swap or treasury-inspect golden mechanisms beyond what
  INV-3 requires.
